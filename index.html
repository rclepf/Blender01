Por que Blender, e por que isso importa para jogos

O Blender é um software de criação 3D completo — modelagem, escultura, UV, materiais, iluminação, rigging, animação, simulação, compositing e até edição de vídeo — e é gratuito e de código aberto. É o motivo de ser o software 3D mais usado por estúdios indie e por quem está aprendendo: dá para ir do zero a um asset pronto para engine sem pagar nenhuma licença.

Nesta UC, o Blender entra depois da parte 2D (Illustrator/Photoshop): o logotipo e a concept art definem a identidade visual do jogo; o Blender é onde essa identidade vira objeto no espaço — um prop, um cenário, um personagem — pronto para ser importado numa engine como Unity, Unreal ou Godot.

O que você vai conseguir fazer até o Site 6

Modelar um objeto do zero, prepará-lo com UV e material PBR, otimizá-lo para tempo real e exportá-lo num formato que qualquer engine de jogo entende. O Site 7 acrescenta rigging e uma animação simples sobre o mesmo objeto.

Viewport 3D

Onde você vê e manipula os objetos. É a maior área da tela e onde você vai passar praticamente todo o tempo desta série.

Outliner

Lista em árvore de tudo que existe na cena: objetos, coleções, luzes, câmeras. Renomear e organizar aqui evita caos quando o projeto cresce.

Properties

Painel de abas à direita — cada ícone é uma categoria (objeto, modificadores, material, física...). Vamos usar principalmente Object, Modifier e Material nesta série.

Header / Modos

Barra superior do viewport mostra o modo ativo (Object, Edit...) e ferramentas de snapping que vamos usar a partir do Site 2.

Dica prática

Todo painel do Blender pode ser redimensionado arrastando a borda entre eles, e a maioria pode ser dividido em dois. Não existe "layout errado" — ajuste até sobrar espaço confortável para o viewport, que é onde o trabalho realmente acontece.

03

Object Mode × Edit Mode

A distinção mais importante de toda a série — tudo que vem depois depende de saber em qual dos dois você está.

Object Mode

  • Move, rotaciona e escala o objeto inteiro
  • Onde você organiza a cena, aplica modificadores e exporta
  • Cada objeto aparece como um item independente no Outliner
  • Modo padrão ao abrir o Blender

Edit Mode

  • Edita a malha por dentro: vértices, arestas e faces
  • É aqui que a modelagem de fato acontece (Site 2 em diante)
  • Alterna entre seleção de Vertex / Edge / Face com 1 2 3
  • Só existe para um objeto do tipo malha por vez
Alternar entre os dois

Tecla Tab com o objeto selecionado. É provavelmente a tecla que você mais vai apertar em toda a série — memorize antes de seguir para o Site 2.

04

Transformações e eixos

Três teclas resolvem praticamente toda a manipulação de objetos: G, R, S.

X — vermelho
Y — verde
Z — azul, "para cima"

Essas três cores aparecem em todo lugar no Blender — no gizmo de transformação, no N-panel, no eixo do viewport — e valem a pena fixar agora: vão reaparecer em UV (Site 3) e em rigging (Site 7).

TeclaAçãoRestringir a um eixo
GGrab / moverG X move só no X (e Y, Z do mesmo jeito)
RRotate / rotacionarR Z gira só em torno do eixo Z
SScale / escalarS Shift+Z escala em tudo, exceto Z

Depois de pressionar a tecla, digite um número para um valor exato — G X 2 Enter move exatamente 2 unidades no eixo X. Isso é mais rápido e mais preciso do que arrastar com o mouse, e vira hábito rapidamente.

Painel N

Tecla N dentro do viewport abre um painel lateral com a posição, rotação e escala exatas do objeto selecionado — útil para conferir ou digitar valores diretamente, em vez de estimar visualmente.

05

Organização da cena e preferências essenciais

Hábitos que evitam retrabalho nos próximos seis sites.

✓

Renomeie objetos no Outliner

Duplo clique no nome. Um projeto com "Cube.003" e "Cube.004" é impossível de organizar depois — chame de "Bau_Corpo" e "Bau_Tampa" desde o início.

✓

Use Collections para agrupar

Botão direito no Outliner → New Collection. Separe, por exemplo, "Props" de "Referência" — facilita esconder e exportar apenas o necessário.

✓

Unidades em métrico

Properties → Scene → Units → Metric, com Unit Scale = 1 (1 unidade do Blender = 1 metro). Engines de jogo trabalham em metros — alinhar isso agora evita assets com escala errada no Site 6.

✓

Auto Save ativado

Edit → Preferences → Save & Load → Auto Save. Já vem ativo por padrão, mas vale confirmar o intervalo (2–5 minutos é razoável).

✓

Salve incrementalmente

Ctrl+Shift+S com um número no nome do arquivo (bau_v01.blend, bau_v02.blend...). Se algo quebrar, você volta para uma versão anterior em vez de recomeçar.

06

Modelar para quê? Jogos × Animação × Impressão 3D

O mesmo Blender, a mesma malha — mas as regras de topologia mudam completamente conforme o destino final.

Esta série é focada em modelagem para jogos, mas entender as outras duas finalidades ajuda a explicar por que vamos priorizar certas decisões (poucos polígonos, UV eficiente) em vez de outras.

Critério Jogos (tempo real) Animação Impressão 3D
Prioridade Baixa contagem de polígonos, performance Topologia que deforma bem ao mover Malha fisicamente imprimível
Topologia ideal O mínimo de polígonos que ainda lê bem visualmente; detalhe "falso" via normal map Quads bem distribuídos, edge loops seguindo músculos e articulações Não precisa seguir regra de fluxo — precisa ser sólida
Requisito técnico central UV bem organizada (Site 3) para receber textura Rig limpo por baixo da malha (armature + weight paint) Malha manifold — fechada, sem furos ou faces soltas
O que quebra o resultado Polígonos demais (queda de FPS), UV mal distribuída (textura esticada) Poucos loops nas articulações (deformação "quebrada" ao animar) Geometria não-manifold (a peça "não existe" fisicamente e não fatia)
Formato de saída típico .fbx / .glb, importado numa engine (Site 6) .blend nativo, ou exportado com rig para outro software de animação .stl / .obj, aberto num fatiador (slicer)
Por que isso importa desde já

Um objeto modelado pensando em impressão 3D costuma ter polígonos demais para uma engine de jogo rodar em tempo real. Um objeto pensado para animação tem edge loops que um prop estático (como nosso baú) simplesmente não precisa. Cada decisão de modelagem, a partir do Site 2, vai ser tomada com a coluna "Jogos" desta tabela em mente.

O prop-guia da série: o Baú do Tesouro

O mesmo objeto atravessa os nove sites — modelado, texturizado, otimizado, exportado e, por fim, animado.

Por que um baú?

É um prop clássico de jogo, simples o bastante para modelar em poucas formas primitivas (corpo + tampa), com dois materiais naturais (madeira e metal) e uma "junta" óbvia — a tampa — que se torna o exemplo perfeito de rig simples no Site 7.

Exercício guiado — antes de seguir em frente

Prática de 10 minutos

Configure o arquivo que vai virar o baú do tesouro

  1. Abra o Blender. Selecione o cubo padrão e delete (X → Delete, ou tecla Delete).
  2. Adicione um novo cubo: Shift+A → Mesh → Cube.
  3. Renomeie esse objeto no Outliner para Bau_Corpo (duplo clique no nome).
  4. Pratique as três transformações: mova com G, rotacione com R, escale com S — teste restringindo a um eixo (X, Y ou Z) depois de cada tecla.
  5. Alterne para Edit Mode com Tab, observe os vértices, arestas e faces do cubo, e volte para Object Mode.
  6. Abra o painel N (tecla N) e zere a rotação e ajuste a escala para 1,1,1 — deixando o objeto "limpo" para o Site 2.
  7. Confirme as unidades da cena em métrico (Properties → Scene → Units) e salve o arquivo como bau_v01.blend.

Esse arquivo é o ponto de partida do Site 2, onde o cubo deixa de ser um cubo e começa a virar, de fato, um baú.
